= TCK
:description: Standalone official TCK runners and historical evidence.

The official Persistence 3.2 and Validation 3.1 runners stay outside the reactor.
Run from the repository root:

[source,sh]
----
noether-persistence/noether-jpa-tck/run-official-tck-persistence-3.2.sh
noether-validation/noether-validation-tck/run-official-tck-validation-3.1.sh
noether-persistence/check-validation-neutrality.sh
----

The official artifact checksums and TCK-BUG-001 byte-exact derived-jar fixture
patch are unchanged; original artifacts are never edited. `TCK_FIXTURES=official`
selects the untouched Persistence fixture. See the runner README for setup.

== Current SQL to-one fetch join verification (2026-10-16)

After decision D11 (eligible to-one fetch joins read from the owner's SQL row), the new
SQL-counting `FetchJoinTest` was red first (10 select-count failures) and now passes 14 tests;
`./mvnw -ntp clean install` passes 848 reactor tests (zero failures, errors or skips). The full
patched PostgreSQL 17 run below retains 2135 tests, 2131 passes, zero failures/errors and the
four unchanged official skips, aggregated from all 259 XML reports. Fixture hashes are unchanged.

== Lazy to-one verification (2026-10-15)

After the bounded lazy to-one follow-up, `./mvnw -ntp clean install` passes 834 reactor tests
(zero failures, errors or skips). The focused SQL/generation/module regressions pass 53 tests,
including 18 new lazy to-one scenarios, the unchanged 19 lazy-collection scenarios, static
generation inside a closed application module and eager fallback in an opened module without
a provider read edge.

[source,sh]
----
TCK_FIXTURES=patched TCK_VALIDATION=off \
  ./noether-persistence/noether-jpa-tck/run-official-tck-persistence-3.2.sh
----

The full PostgreSQL 17 run on Temurin 25.0.4 / Maven 3.9.16 retains 2135 tests, 2131 passes,
zero failures, zero errors and four unchanged official skips. All 259 XML reports were parsed
independently of the wrapper's exit status; official and derived fixture hashes are unchanged.
This is a local patched result, not certification or an untouched official result.
