= What's new
:description: Noether extraction and compatibility changes.

== 2026-10-15 — SQL collection fetch joins

One eligible JPQL or Criteria inner/left collection fetch now returns owner and elements
from the same SQL statement. Entity and basic/embeddable element collections retain list
positions/map keys, managed identity, dirty state and in-place unloaded wrappers.
Snapshots, callbacks and cache publication see complete collections. `DISTINCT` deduplicates
managed owner identities, not bag values or application equality.

Complex/multiple/polymorphic fetches retain complete secondary loading. Pagination uses
SQL distinct-owner paging followed by complete secondary loads for single-root selections
with scalar root ordering; unsupported projections/grouping/locks/element ordering fail
explicitly before SQL. No partial collections or silent in-memory pagination.
Batching remains the next prioritized lot. See xref:internals.adoc[] and xref:tck.adoc[].
The preexisting D11 date below is retained as recorded, not rewritten by this delivery.

== 2026-10-16 — SQL to-one fetch joins

JPQL `JOIN FETCH` / `LEFT JOIN FETCH` and Criteria `fetch` of to-one relationships now load the
owner and its fetched targets from one SQL statement instead of a select per target, keeping
one managed instance per identity, hydrating unloaded references in place and never overwriting
managed instances. `DISTINCT`, grouped, locking and nested queries, polymorphic or
joined/table-per-class targets, collection fetches, entity graph hints and `find` keep the
previous follow-up selects. Collection fetch hydration and batching are not part of this change.

== 2026-10-15 — Bounded lazy to-one references

Owning LAZY `@ManyToOne`/`@OneToOne` foreign-key properties can defer their target row
through a JDK Class-File API subclass generated by APT (closed application module) or
at bootstrap (opaque archive with package opens). A simple identifier getter needs no SQL;
other intercepted getters and setters initialize the same managed instance once.
Missing and detached references fail explicitly, while eager fetch plans still initialize.
Unsupported shapes remain eager: field access, final forms, inverse one-to-one, join tables,
embedded paths, hierarchy/composite/derived identifiers and XML-only/remapped target identifiers.
Final entity classes are accepted as a non-portable eager-only extension.
See xref:concepts.adoc[] and xref:internals.adoc[] for the exact boundaries.

== 2026-10-15 — Lazy collections

`@OneToMany`, `@ManyToMany` and `@ElementCollection` attributes that are `LAZY` (the default)
are no longer read with their owner: the first access loads them once in the owner's
persistence context. `PersistenceUnitUtil.isLoaded` reports their state without SQL.
Accessing an unloaded collection after `clear`, `detach`, `close` or serialization now throws
`PersistenceException`; touch the collection, use `JOIN FETCH`, a fetch/load graph or
`FetchType.EAGER` before detaching. To-one references are covered by the separate bounded follow-up above.
The full patched Persistence TCK result is unchanged (2135 tests, 2131 passed, four official skips).

== 2026-10-11 — Independent Noether repository

Persistence and the provisional Validation implementation moved from Mansart
to Noether with their filtered Git history. Maven artifacts now use
`io.vidocq.noether:noether-*`; packages, Java modules, generated accessors and
service registrations use `io.vidocq.noether`.

The provider is `io.vidocq.noether.jpa.core.NoetherPersistenceProvider`.
Mansart Pool, Transactions and Data remain unchanged.
Validation publishing remains blocked. Historical TCK/benchmark/bug evidence
is retained verbatim and labelled; extraction is not a new measurement or
certification claim. See xref:migration.adoc[migration instructions].
